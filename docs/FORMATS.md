## Great Library block editing contract

The first Python model for `*_Great_Library.txt` is source-preserving and in-memory; it does not write directly to a project file. It indexes top-level `[KEY]` header lines and standalone `[END]` lines, then replaces only a unique, structurally closed existing block's body span.

| Stage | Mechanism | Tag | Requirements |
|---|---|---|---|
| INGEST | Retain source bytes and decode CP1252 | [mandatory] | R1 |
| INDEX | Capture exact key and body byte spans, retaining malformed blocks as ineligible | [mandatory] | R2-R5 |
| REPLACE | Replace one unique closed key's body in memory | [mandatory] | R6-R8 |
| SERVE | Return exact original bytes when unchanged, otherwise patch source spans | [mandatory] | R9-R10 |

R1. WHEN bytes are loaded, retain exact source bytes; decode only header keys as CP1252 so unrelated body bytes remain opaque.
R2. WHEN a complete physical line is `[KEY]`, begin a block; WHEN a complete physical line is `[END]`, close the current block. Inline `[END]` text is body content.
R3. WHEN a new header appears before the current block has a standalone `[END]`, mark the prior block unclosed and continue indexing later blocks without mutation to source.
R4. WHEN `[END]` appears without an open block or input ends with an open block, retain the source but do not make an invalid block editable.
R5. WHEN keys repeat, retain each occurrence in source order; do not select a winner.
R6. WHEN reading a key, require exactly one matching closed block and return its current body bytes.
R7. WHEN replacing a key, require exactly one matching closed block and a CP1252-encodable string; reject missing, duplicate, unclosed, or unencodable values before changing model state.
R8. WHEN replacement text lacks a final line ending and the captured body had one, retain that exact line ending before `[END]`.
R9. WHEN no key has changed, return the original bytes exactly.
R10. WHEN keys are replaced, patch only their captured body spans in reverse order; retain all other bytes and block order.

CLOSED
- Do not insert missing blocks or choose a winner for duplicate keys; native add/duplicate semantics are not established.
- Do not infer `.gls` cell meanings or perform project-file writes in this model.
- Keep CTPEd output parity open; the block layout is observed in a later game corpus.

Preconditions: input is a Great Library text file with top-level bracketed key lines and `[END]` terminator lines. Parsing preserves malformed blocks; lookup/update of missing, ambiguous, or unclosed blocks and unencodable replacement text raise without mutating the model.

Validation (2026-10-16): `tests/test_great_library.py` passes five independently authored fixtures for LF, CRLF, inline `[END]` payloads, malformed/unclosed blocks, duplicate and missing keys, unencodable text, and opaque bytes. At this model milestone, the full suite passed 370 tests with 1 skip in 12.04s. The installed English `Great_Library.txt` scan indexes 1,952 blocks (1,951 closed, one unclosed), finds no duplicate keys, and successfully replaces/reparses `ADVANCE_AGRICULTURE_PREREQ` in memory while the source file remains unchanged.

## Stage B contract

Stage B's portable file-access core reads a file as bytes and writes those same bytes unchanged. It does not decode, normalize line endings, interpret delimiters, or turn a missing path into an empty file. A failed read/write is surfaced to the caller. Parsing and serialization belong to the format-aware model in Stage C.

`FileInterface` is represented by a headless path service: the CLI supplies explicit open/save paths, open requires an existing file, and save requires an existing parent directory. `FileReference` binds a file name to a directory and exposes the resulting path, absence check, and existence assertion. These replace the recovered COM path/dialog interface at the CLI boundary; no guessed file dialog behavior is part of the contract.

Acceptance evidence: round-trip copies of every non-executable distribution sample through the byte-access functions; varied byte inputs including empty, CRLF text, and arbitrary binary bytes; and path checks for existing, missing, and invalid-parent cases. The source samples remain read-only. These checks establish lossless access only, not correctness of the absent game-data parsers.

## Stage C contract: `Entry` boundary reader

The recovered `Entry.ReadFromFile` checks the declared format and has separate branches for formats 1 and 3. The Python reader captures record boundaries and names, then optionally binds field occurrences to `FieldInstance` objects while retaining their raw value representation. - The file chooser belongs to the visual boundary; descriptor/data loading and unchanged-copy saving remain callable functions so the behavior can be checked without opening a window.
- Directory chooser results and direct explicit relative roots resolve from the process working directory; relative declaration paths without `%s/%c` remain anchored to the `.ced` directory.
- Start the window with `python src/app.py`; tkinter is supplied by Python on standard desktop installations.
- Loading an invalid descriptor displays an error and keeps the current document intact.
- Saving a descriptor, project, or unchanged preferences file writes original bytes; saving an unchanged data file writes original bytes, preserving encoding, line endings, comments, and whitespace. Supported format-1/3 edits patch only the selected scalar token; schema-bound nested format-1 edits patch the selected child token through captured parent block spans. Preference flag token patching is available in the model.
- Loading a new descriptor clears any data file parsed against the old descriptor; parse failure leaves the current view intact.
- Format-0 editing requires an editable File and preserves CP1252 plus the source newline convention. Format-2 editing requires an editable File and writes CP1252 with CRLF. Format-3 editing requires one scalar FieldInstance; format-1 editing accepts source-spanned string FieldInstances in the root or schema-bound nested Entries. Both require an editable File; unbound nested raw blocks and value conversion remain open.
